# Auth Admin

## Organization identity connections

Use `auth.admin.connection` to manage organization-owned OIDC connections.
Each connection stores an issuer, client ID, optional resource URI, email
domains, SSO-required policy, and JIT membership settings. OIDC secrets stay in
the application's secret store; the connection stores only a `credentialRef`.
These records are separate from `auth.social.providers` and from
`auth.admin.authorizationServer.client`, which manages applications using
Athena as their issuer.

Signing in through a connection does not select its organization as the
session's active organization. The client must select an organization after
sign-in through the normal session organization API.

The current Embedded Auth admin routes require an Athena administrator session.

## Local role helpers (`@xylex-group/athena/admin`)

Do **not** copy a local `hasAdminRole` — use the package:

```ts
import {
  hasAdminRole,
  hasAdminPermission,
  resolveAdminPermission,
  resolveAdminPermissionClient,
} from "@xylex-group/athena/admin"

hasAdminRole(session)
// true when session.user.role is a comma-separated list containing "admin"
// (case-insensitive): "admin", "ADMIN", "member, admin", …

await hasAdminPermission(client, {
  session,
  permissions: ["admin:read"],
})

const guard = await resolveAdminPermission(client, {
  session,
  permissions: ["admin:read"],
})
// { ok: true, session } | { ok: false, status: 401 | 403, error }

// createClient(...) or auth bindings both work:
resolveAdminPermissionClient(createClient(...))
resolveAdminPermissionClient(createClient(...).auth)
```

### React hook (`@xylex-group/athena/react`)

```ts
import { useAdminPermission } from "@xylex-group/athena/react"

const { allowed, isPending, session } = useAdminPermission(athena, {
  permissions: ["admin:read"],
})
```

For TanStack Query gates in Auth UI (sidebar, table showcase, workspace), use
`useHasAdminAccess` / `checkAdminPermissions` from
`@xylex-group/athena-auth-ui` — they call the same admin helpers under the hood.

`hasAdminRole` only inspects the session payload. It is not organization
membership — see [Organization membership](../organization-membership.md).

## Authorization Server clients and grants

`authorizationServer.client` registers and manages applications that use
Athena as their OAuth issuer. Creation accepts `clientName`, `redirectUris`,
`resourceUris`, `scopes`, and optional `clientUrl` / `metadata`. The server
generates the ID and fixes the supported protocol values to public,
pre-registered authorization-code clients without client authentication.
Clients can be listed, retrieved, updated, or disabled; there is no delete
operation.

`authorizationServer.grant.list()` filters delegated authorizations by user,
client, organization, and resource. `grant.revoke()` records the current admin
as the revoking principal.

These Embedded Auth routes use the canonical Authorization Server stores and
are not served by the dedicated Rust runtime. Dedicated Rust manages the
separate Social Callback Registration allowlist at
`/admin/social-callback-registration/*`. Its old `/admin/oauth-client/*` paths
are deprecated aliases with no SDK binding. `auth.social.providers` continues
to configure upstream social identity providers.

## React Email payload support

For routes that accept HTML (`/admin/email/create`, `/admin/email/update`, `/admin/email-template/create`, `/admin/email-template/update`), you can pass:

```ts
react: {
  element?: <YourEmailComponent />,
  component?: YourEmailComponent,
  props?: { ...templateProps },
  pretty?: boolean,
  text?: string,
  includePlainText?: boolean,
}
```

When `react` is present, the SDK renders `element` to `htmlBody` or `htmlTemplate` before sending.
For template routes, `variables` is auto-derived from `react.props` when omitted.
Canonical template payload fields are snake_case: `template_key`, `event_type`, `subject_template`, `text_template`, `html_template`, `variable_bindings`, `attachments`, `attachment_failure_mode`, and `is_active`.
Legacy camelCase request keys such as `templateKey`, `eventType`, `subjectTemplate`, `variableBindings`, `attachmentFailureMode`, and `isActive` are still accepted for compatibility, but responses for this surface are snake_case.
For template routes, the SDK rejects payloads with more than `64` variables or variable names longer than `128` characters.
For reusable flows, prefer `defineAuthEmailTemplate(...)` from the root SDK export.

The backend limit constants are also exported from the SDK:

- `ATHENA_AUTH_ADMIN_LIMITS`
- `ATHENA_AUTH_MAX_ADMIN_JSON_BYTES`
- `ATHENA_AUTH_MAX_ADMIN_JSON_DEPTH`
- `ATHENA_AUTH_MAX_TEMPLATE_VARIABLES`
- `ATHENA_AUTH_MAX_TEMPLATE_VARIABLE_LENGTH`

## Examples

```ts
import { client } from "./auth-client"

await client.auth.admin.role.set({
  userId: "usr_1",
  role: "admin",
})

await client.auth.admin.user.list()
await client.auth.admin.user.session.list({ userId: "usr_1" })

await client.auth.admin.user.create({
  email: "new-user@example.com",
  password: "temporary-password",
})

await client.auth.admin.user.unban({ userId: "usr_1" })
await client.auth.admin.user.ban({ userId: "usr_2", banReason: "policy violation" })

await client.auth.admin.user.impersonate({ userId: "usr_3" })
await client.auth.admin.user.stopImpersonating({ userId: "usr_3" })

// single payload -> /admin/revoke-user-session
await client.auth.admin.user.session.revoke({
  userId: "usr_3",
  sessionToken: "sess_token_1",
})

// multiple payloads -> /admin/revoke-user-sessions
await client.auth.admin.user.session.revoke([
  { userId: "usr_3", sessionToken: "sess_token_2" },
  { userId: "usr_3", sessionToken: "sess_token_3" },
])

// direct plural payload -> /admin/revoke-user-sessions
await client.auth.admin.user.session.revoke({
  userId: "usr_3",
})

await client.auth.admin.user.remove({ userId: "usr_4" })
await client.auth.admin.user.setPassword({
  userId: "usr_4",
  newPassword: "new-password",
})

await client.auth.admin.hasPermission({
  permissions: { users: ["manage"] },
})

const adminGuard = await client.auth.admin.requirePermission({
  permissions: { users: ["manage"] },
})

if (!adminGuard.ok) {
  return new Response(JSON.stringify({ error: adminGuard.error }), {
    status: adminGuard.status,
  })
}

const currentSession = adminGuard.session

`athena-js` also ships framework-agnostic admin helpers under `@xylex-group/athena/admin`
for local role checks and simple server-side guard composition:

```ts
import {
  hasAdminPermission,
  hasAdminRole,
  resolveAdminPermission,
} from "@xylex-group/athena/admin"

if (hasAdminRole(currentSession)) {
  console.log("local admin role present")
}

const allowed = await hasAdminPermission(client, {
  session: currentSession,
  permissions: { users: ["manage"] },
})

const permission = await resolveAdminPermission(client, {
  session: currentSession,
  permissions: { users: ["manage"] },
})

if (!permission.ok) {
  return new Response(JSON.stringify({ error: permission.error }), {
    status: permission.status,
  })
}
```
