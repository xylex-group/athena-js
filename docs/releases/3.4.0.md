# Release 3.4.0 — `@xylex-group/athena`

Cloudflare edge-local adapter: run the same Athena JS client against Worker **D1** and optional **R2** bindings without an `athena_rs` hop.

## Install

```bash
pnpm add @xylex-group/athena@3.4.0
```

```ts
import { createClient } from '@xylex-group/athena'
// optional façades
import {
  createCloudflareClient,
  createAthenaFromWorkerEnv,
  createAthenaRuntime,
} from '@xylex-group/athena/cloudflare'
```

## What’s new

| Area | Summary |
| --- | --- |
| **Drop-in edge** | `createClient({ db: { d1 }, storage: { r2 } })` or top-level `d1` / `r2` aliases |
| **`@xylex-group/athena/cloudflare`** | `createCloudflareClient`, `createAthenaRuntime`, `createAthenaFromWorkerEnv`, mode helpers |
| **Switchable runtime** | `mode: 'auto' \| 'edge' \| 'gateway'` + `prefer` when both D1 and URL exist |
| **Hybrid** | Local D1/R2 + remote auth/billing via root `url` / `key` |
| **`client.capabilities`** | Honest feature detection (`mode`, layers, storage, auth) |
| **L0/L1 D1** | Raw `query` + flat CRUD SQL compile; unfiltered mutations rejected; range-bounded updates/deletes |
| **L3a R2** | `putObject` / `getObject` / `deleteObject` / `listObjects` (no catalogs/backups) |

## Security

- Removed unused `uuid` dependency (GHSA-w5hq-g745-h8pq).
- D1 compiler: only identifier/alias SELECT lists; strict table/column identifiers.
- R2: reject empty keys, null bytes, and `..` segments under storage prefixes.
- `npm audit` clean at release for production and development dependencies.

## Upgrade checklist (consumer)

1. Prefer `createClient({ db: { d1: env.DB }, storage: { r2: env.FILES } })` in new Worker code.
2. Use `mode: 'auto'` + `prefer` when both edge bindings and gateway URL are configured.
3. Rely on `client.capabilities` instead of environment sniffing for feature gates.
4. Do not pass raw SQL expressions into `.select()` on edge — column names / aliases only.
5. Keep R2 object keys free of `..` segments; configure a per-app `storage.prefix` / `storagePrefix`.

## Pair with

Workers using D1/R2 bindings; optional remote Athena root for auth/billing. Gateway-only consumers can ignore this release surface.
